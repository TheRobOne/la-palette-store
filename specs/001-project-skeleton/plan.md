# Implementation Plan: Project Skeleton

**Branch**: `001-project-skeleton` | **Date**: 2026-09-28 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-project-skeleton/spec.md`

## Summary

Scaffold the store with `create-medusa-app` (pnpm workspace: `apps/backend` Medusa 2 +
Admin, `apps/storefront` Next.js Starter), bump everything to latest majors, point it at a
Railway-hosted **dev** Postgres (no Docker, no Redis), configure Poland (PLN, gross prices,
8% VAT) through an idempotent seed with fictional products carrying catering attributes
from a small custom `catering` module, and restyle the storefront shell with La Palette
Garden tokens, fonts and assets. CI is a single GitHub Actions job (lint, typecheck, unit
tests, build — no database). Railway auto-deploys a public, non-indexed **staging**
environment from `main` after CI passes.

## Technical Context

**Language/Version**: TypeScript 7 (backend gated, fallback 6.x — research R-04), Node.js 24 LTS

**Primary Dependencies**: Medusa 2.21.2, Next.js 16 (Medusa Starter Storefront), React 19 (storefront) / React 18 (Admin extensions), Tailwind CSS 4, pnpm 12 workspaces

**Storage**: PostgreSQL on Railway (dev + staging databases); Medusa in-memory event bus/workflows/locking/cache; local file provider for committed placeholder images

**Testing**: Jest 30 + `@medusajs/test-utils` (backend unit in CI, integration locally), `node --test` (storefront unit), Playwright 1.63 + axe (local e2e smoke)

**Target Platform**: Local macOS (native Node, no containers); staging on Railway

**Project Type**: Web application — commerce backend + SSR storefront (pnpm monorepo)

**Performance Goals**: Core Web Vitals "good" on `/pl`; `/status` < 1 s

**Constraints**: 3 commands to run locally; CI < 5 min without DB/secrets; staging live < 15 min after merge; ≥ 360 px; no secrets in git; staging `noindex`

**Scale/Scope**: Very small shop, 1 developer; 2 apps, 1 custom module, 6 sample products, 1 CI job, Railway project with `dev` (Postgres) and `staging` (Postgres, backend, storefront) environments

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| React 18 (not latest 19) in `apps/backend` Admin extensions | `@medusajs/dashboard` 2.21.2 depends on `react@^18.3.1`; extensions share its React | React 19 there breaks Admin (duplicate React); patching Medusa is prohibited |
| (Conditional) TypeScript 6.x in `apps/backend` | Only if the R-04 gate shows `medusa build` fails on TS 7 | TS 7 would leave the backend unbuildable |
| (Conditional) Any starter dependency kept below latest major | Only if a bump breaks the Medusa Starter and a fix is disproportionate | Documented per package at implementation time |
| Railway `dev` environment with its own Postgres | Constitution: separate dev/staging DBs, no Docker locally | Sharing staging DB is forbidden; local Postgres needs extra install |
